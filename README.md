# Portsmith-iOS

An agent-friendly workbench for researching and bringing up XNU/iOS on non-Apple ARM64 devices.

Portsmith is a **workspace and toolbox**, not a mash-up of every port's kernel and drivers. Device ports remain separate full repositories in `ports/<port>/repo/`; shared frameworks and optional research references live under `sources/`. Workflows, skills, docs, and host-side utilities live here. Port and framework submodule pins and component snapshot manifests record exact reviewed revisions.

> Experimental platform research only. Do not use a phone with irreplaceable data. Never flash or reset a device without explicit, current authorization and a verified restore path.

## Start here

Clone the workbench and initialize its direct port/framework submodules (without recursively following UniXNU’s nested component pins):

```sh
git clone https://github.com/Chromitsune/Portsmith-iOS.git
cd Portsmith-iOS
python3 tools/checkout-sources.py --curated
```

This initializes the 12 curated port sources and shared UniXNU framework; reference-only sources such as Onyx, Axon 7, and viva-gpu remain optional and can be selected with `python3 tools/checkout-sources.py --reference <source-name>` (for example, `hackios-xnu-kernel-onyx`, `zte-axon7`, or `viva-gpu`). The 79 available-device catalog source references are optional: initialize one with `python3 tools/checkout-sources.py --name sheng`, or all accessible ones with `--available`. Do **not** use recursive submodule initialization; see [`sources/README.md`](sources/README.md) for a pinned nested UniXNU commit unavailable upstream. License-cleared shared components are already vendored under `components/`.

1. Read [`AGENTS.md`](AGENTS.md) for workspace navigation and safety rules.
2. Read the relevant [`ports/<device>/AGENTS.md`](ports/README.md) and source project notes.
3. Run host-only checks before any hardware test; distinguish host-verified from device-verified results.

## Layout

- `AGENTS.md` — workspace instructions for agents.
- `docs/architecture.md` — repository boundaries, evidence labels, and source/license rules.
- `ports/` — curated per-device `AGENTS.md`/manifests and source under `repo/`; `ports/catalog/` separately indexes the full UniXNU device list and optional available-record source submodules. Most curated ports are pinned Git submodules; Dada is a vendored snapshot with its original README, notices, and licenses retained.
- `components/` — license-audited upstream source snapshots grouped by function/hardware scope, plus cross-port compatibility notes. Each snapshot retains its own license/notices and exact source pin; unresolved mixed/unlicensed repositories remain catalog-only.
- `sources/` — shared framework and optional research-source references (UniXNU and, for example, the reference-only `viva-gpu` tree).
- `skills/` — reusable task playbooks.
- `tools/` — cross-port utilities. `tools/portsmith.py` inventories curated ports, queries the full device catalog, groups by vendor/SoC/storage/GPU/bootloader, lists shared components, checks source pins, and reports host tools without touching a device. `tools/checkout-sources.py` initializes curated, selected available, or named reference-only submodules (for example, `--reference viva-gpu` or `--reference zte-axon7`); `tools/import-unixnu-available-sources.py --dry-run` previews the audited catalog-source imports. `tools/portsmith-image-tools` contains a reviewed, MIT-licensed subset adapted from iOSPlus10's generic image/IPSW tooling; Negroni-only `ctl` and `bootlog` commands are intentionally excluded.
- `docs/` — design notes and contribution/evidence conventions.

## Repository scope

Portsmith is a research/coordination workspace for XNU/iOS bring-up on non-Apple ARM64 hardware—not a universal OS image or a claim that every catalog entry works.

- **12 curated Portsmith device-port records** have hand-maintained agent notes, pinned sources, hardware metadata and safety guidance. In addition, 78 catalog-derived `ports/<name>/` folders cover the 79 UniXNU `available` records not already represented by the curated sheng folder: 72 have pinned external source submodules and six are metadata-only because their exact source pins were inaccessible. `ports/onyx/` and `ports/axon7/` are reference-only profiles with no Portsmith verification. The compatibility matrix includes all 92 port/reference records; catalog-derived and reference-only entries are not Portsmith-verified ports.
- **All 265 repository records from the pinned UniXNU device catalog** are indexed in [`ports/catalog/unixnu-devices.toml`](ports/catalog/unixnu-devices.toml): 150 legacy format 1 and 115 format 2; 79 marked `available`, 25 `invalid`, 11 `missing`, and 150 with no state. There are 52 named SoC values (one unlabeled), 122 board/codename values, and 48 repeated-board groups (179 records). Of the 79 `available` records, 73 exact revisions were reachable; 72 are pinned as external submodules under top-level `ports/<name>/repo`, one reuses the curated sheng checkout, and six unavailable pins have metadata-only port wrappers. A root-license scan found 54 recognizable root licenses (some with scoped/third-party terms), 16 repositories with no root license, and 3 with mixed or unclear scope; six pinned sources were inaccessible. Submodule pointers are not permission to reuse code. For format 2, `available` means the upstream porting record validated—not that the source builds or the device works.
- **Shared code:** 25 license-audited UniXNU component snapshots plus the MT8167-only NativeMsdc eMMC reference live under `components/`. Two UniXNU component repos remain catalog-only pending license/provenance review. This code is grouped by function/hardware scope and is not assumed to be portable.
- **Evidence and automation:** the README checklist records per-feature upstream reports against exact source pins; host tools validate source/manifest consistency and a weekly watcher opens review PRs when upstream heads move or become unavailable. New commits never automatically become “working” statuses.
- **Not included:** firmware, IPSWs, device dumps, keys, or generated images; full source checkouts for all 265 device records are not mirrored. Additional full ports are added only after source/license, duplicate-device, safety, and evidence review.

Browse/search the full upstream device index with `python3 tools/portsmith.py device-catalog --summary`, `--state available`, `--soc SM8550`, or `--search sheng`. The live Portsmith-managed port list is separate: `python3 tools/portsmith.py ports --group-by <vendor|soc|storage|gpu|bootloader>`.

## Safety and evidence

- Do not flash without explicit authorization. A prior authorization for one test is not standing permission.
- Inspect the phone's current state before any reset; do not force a reset just to collect data.
- Never write `LOGFS`, guess register addresses, or infer DRAM retention from a PSCI reset request.
- Do not commit IPSWs, vendor firmware, device dumps, identifiers, root images, generated payloads, or personal calibration data.
- Label results `host-verified`, `device-verified`, `inferred`, or `unknown`; a build or screenshot alone is not proof of a working port.
